refactor: 改成纯 LibXposed API 102 模块（staticScope + 去掉老式 meta-data）

用户反馈：「102 不太纯粹，要像 Eta 一样只有模块固定的应用出现在列表」。

两个问题，一次解决：

① 作用域列表里出现了别的 app
   根因：module.prop 缺 staticScope。
   官方定义（LSPosed wiki）：
     staticScope: "Indicates whether users should not apply the module
                   on any other app out of scope"
   不写 → 管理器把所有已装应用都列出来、还允许勾选。
   我们只在 SystemUI 挂钩、代码里也没有 requestScope 动态申请，
   所以必须为 true。Eta 的 module.prop 实测就有这一行。

② "102 不纯粹"
   根因：manifest 里还留着 4 个老式 meta-data
   （xposedmodule / xposeddescription / xposedminversion / xposedscope）。
   官方原话："Modern API does not use metadata anymore as well.
   Module name uses android:label; module description uses android:description;
   scope list uses META-INF/xposed/scope.list; module configuration uses
   META-INF/xposed/module.prop"
   实测 Eta 的 <application> 里这 4 个 meta-data 数量为 0。全部删除。

module.prop 只留 4 个字段（跟 Eta 一致）：
  minApiVersion / targetApiVersion / staticScope=true / exceptionMode=protective
去掉 id / name / version / versionCode / author / description ——
这些框架从 PackageInfo 和 ApplicationInfo 拿，不用重复写。

随之删除：
  - res/values/arrays.xml（xposed_scope 数组，只被老 meta-data 引用）
  - res/raw/keep.xml（keep 的那几个资源已不存在；
    xposed_description 被 android:description 引用，是静态引用，R8 不会裁）
  - strings.xml 里的 xposeddescription / xposedminversion

验收：
  aapt2 dump xmltree → xposed meta-data 数量 0，android:description 在
  aapt2 dump resources → xposed_description 值仍是真实中文描述
  unzip module.prop → staticScope=true；scope.list → com.android.systemui
  java_init.list → com.iamcanincan.noticon.entry.NoticonModule（R8 未改名）
真机：install -r + 重启 SystemUI，挂钩 10 条，framework=Vector api=102，无新异常。
