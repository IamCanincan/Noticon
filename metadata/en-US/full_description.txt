# Noticon

An Xposed module that **replaces unthemed notification small icons**. Icons that are already monochrome are left untouched.

Android 12 and later force-tint notification small icons: apps that didn't ship a monochrome variant get rendered as a single gray blob you can't tell apart at a glance. Noticon fixes exactly that.

## Two modes

The app has a launcher entry and a settings screen; pick a mode there and it applies right away — no reboot needed for mode changes. New notifications are rendered with the mode you picked; the ones already sitting in the shade keep their icon until they are loaded again.

- **Colored launcher icon** (default): swap the unthemed icon for the app's own launcher icon, original colors kept.
- **System monochrome**: compress the app's own small icon into a monochrome silhouette and let the system tint it like every other notification.

Either way, icons that are already monochrome are never touched.

## Highlights

- **Only touches unthemed icons**: uses the same grayscale check as the system to detect apps that already adapted.
- **Sized to fill**: adaptive icons are rasterized with ~61% of the canvas empty in the middle; the module crops that away and scales the rest up, otherwise the icon ends up small and blurry at notification size.
- **Material 3 Expressive UI**: Compose + Material3, with dynamic color on Android 12+.
- **Scoped to SystemUI only**: hooks are installed only into `com.android.systemui`. No other process is touched.
- **No background network use**: the only request the app ever makes is the one you trigger
  yourself by tapping "Check for updates" — a single read of the latest GitHub release to compare
  version numbers. If `api.github.com` is unreachable (DNS-blocked on many networks), it falls
  back to the public `gh-proxy.com` mirror of the same API. No polling, no analytics, no
  telemetry, no ads. The hooked code that runs inside SystemUI does not touch the network at all.

## Requirements

- LibXposed API 102+ (LSPosed, Vector, etc.)
- Android 8.0 (API 26) or later
- Status bar / lock screen permission for the chosen framework

## How to confirm it's working

```bash
adb logcat -s Noticon -d | grep patched
```

If you see `patched <pkg> 2->1 via=monochrome`, the module swapped a resource-type icon for a bitmap — that's the fix landing. The part after `via=` is the mode that was actually used. If the line is empty, every icon on your device is already monochrome and the module correctly did nothing.

The startup line shows which settings were read:

```
options: enabled=true mode=monochrome keepColor=false preserveTinted=true (source=provider)
```

`mode=launcher-icon` is the colored launcher icon, `mode=monochrome` is system monochrome.
`source=` tells you which channel the settings came from — normally `provider`.

## Settings plumbing

The UI writes its own SharedPreferences (file name `noticon`); the module reads them in the
SystemUI process through a read-only ContentProvider the app exposes, guarded by the
signature-level `android.permission.STATUS_BAR`. That way the setting reaches SystemUI without
depending on framework-specific configuration channels. No configuration is required — if the
settings cannot be read, the built-in defaults apply and the module keeps working.

## Build

```bash
./gradlew assembleRelease   # produces an unsigned APK
```

Sign it with `apksigner` (see `README.md` for the exact command) and install.
